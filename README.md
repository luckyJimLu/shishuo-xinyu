# 中国古典文学 · Chinese Classics Reader

一个以中国古典诗文为中心的静态阅读站，现收录《唐诗选读》和《世说新语》，可直接构建并部署到 GitHub Pages。

## 书库与阅读

- **唐诗选读**：366 篇、86 位作者；诗题、作者、诗句检索，诗体筛选，保留分行，支持上一篇 / 下一篇。
- **世说新语**：36 门、1128 则，保留词义注、刘孝标注与已有译文。
- 藏书首页统一入口，各书独立保存最近篇目与条目内阅读位置。
- 书目与阅读器分离：`data/catalog.json` 描述书目，`assets/library.mjs` 负责校验、内容适配和路由，`assets/reader.js` 负责共用交互。

## 功能

- 三十六门完整目录与逐则阅读
- 古籍米黄纸张 / 夜间护眼主题
- 横排 / 竖排一键切换
- 字号调节
- 左侧篇目导航与正文检索
- 阅读进度、章节定位、返回顶部
- 自动记忆主题、字号、排版方式、最近篇目与阅读位置
- 移动端抽屉目录
- 「原文 / 注释 / 译文」分层阅读；译文默认隐藏
- 刘孝标原注可折叠阅读
- 零前端运行时依赖，适合 GitHub Pages

## GitHub Pages

仓库内置 `.github/workflows/pages.yml`。首次使用时，在 GitHub 仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。之后每次 push 到 `main` 都会自动构建并发布。

## 唐诗来源与再生成

唐诗正文来自 [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)，固定版本为 `b8594f81a89752241442f2ce267d6f66f96704ee`。源文件虽名为“唐诗三百首”，实际标签集包含 366 篇，因此站内称“唐诗选读”，不宣称是标准三百首定本。

原始文件、来源摘要和 MIT 许可证位于 `sources/tang-poems/`，站点构建也保留数据许可证。OpenCC 仅在导入时转换简体，浏览器没有额外运行时依赖。正文保留该来源的异文，例如《静夜思》为“床前看月光”“举头望山月”，未擅自改写为通行教材版本；本批不附生成式注释或译文。

```bash
npm run import:tang-poems  # 从固定本地数据确定性生成，不联网
npm run check             # 同时校验书目、唐诗数据、许可及原有刘注
```

## 多书目路由与兼容

- `#/`：藏书首页，始终可选择两类作品。
- `#/book/tang-poems`：唐诗目录；同一目录支持诗题、作者、诗体及诗句筛选。
- `#/book/<book-id>/read/<work-id>`：稳定的篇目地址；诗题重名不会发生碰撞。
- 原有 `#/chapter/德行` 等链接会自动转入《世说新语》的新地址。

主题、字号、排版沿用原有偏好键；阅读进度改按书目保存为 `classics:<book-id>:positions`，首次打开《世说新语》时兼容旧 `ssxy_pos` 数据。首页提供继续阅读入口，不自动跳过书库。检索结果不覆盖正常阅读位置；跨书切换会忽略过期的正文或辅助加载结果。

新增书目时，添加正文 JSON 和 catalog 条目即可复用通用阅读器；`kind` 为 `prose` 或 `poetry`。诗歌条目必须有稳定 `id`、`title`、`author` 和分行 `content`；散文章节由原始顺序生成 `chapter-01` 等编号。所有内容需记录来源与许可，再运行数据校验。仓库名和 Pages 路径保留为 `shishuo-xinyu`，避免破坏既有部署地址。

## 世说新语正文来源与校勘说明

《世说新语》为公版古籍。本仓当前结构化正文初始化自公开古籍 JSON 语料，并以中国哲学书电子化计划（CTP）《世说新语》相关版本作为后续校勘参考。

- CTP: https://ctext.org/shi-shuo-xin-yu/zhs
- 数据初始化参考: https://github.com/hanzhaodeng/chinese-ancient-text
- 阅读器交互设计参考: https://github.com/hoveychen/guwen-reader

> 电子文本可能存在异体字、OCR 或整理误差。重要引文建议回查影印本；后续校勘记录应独立保存，不直接覆盖原始版本。

## 刘孝标注数据层

阅读器使用 `data/liuxiaobiao-notes.json` 保存与正文逐则对齐的刘孝标原注。底本来自 Kanripo / `kr-shadow/KR3` 的《世說新語-劉宋-劉義慶》，许可证为 **CC0-1.0**。

导入器已经从只处理「德行第一」升级为面向 **全书三十六门** 的分门对齐流程：

```bash
npm run import:liu-notes
```

导入时会：

1. 读取仓库内固定版本、记录 SHA-256 的 CC0 Kanripo 底本（支持传入本地路径）；
2. 分离正文与括号内刘孝标注文；
3. 将当前简体正文逐则与古籍底本顺序对齐；
4. 修复底本双栏转写 `/` 造成的阅读顺序；
5. 生成 `data/liuxiaobiao-notes.json`；
6. 生成 `data/liuxiaobiao-alignment-report.json`，记录每门匹配数量、低置信条目和失败条目。

简繁转换仅用于匹配，不修改正文或注文原字形。起点探针相似度达到 0.9，且整则正文相似度达到 0.95，才自动纳入展示；能定位但未达到标准的条目进入复核，找不到可靠起点的条目标记失败。结尾必须从该则正文独立定位，不使用下一个成功条目的起点作为边界。阈值是自动筛选措施，不代表已完成学术校勘。

底本存在卷次跳转，且“赏誉”分为上下两段，因此导入器按门类编号组合底本，不假定全书连续顺序。固定底本和来源摘要保存在 `sources/`；默认导入不联网。

当前 1128 则中：594 则通过自动检查（552 则有刘注、42 则未提取到注），426 则待复核，108 则对齐失败。未通过的条目不展示刘注；完整位置、分数与候选注文见对齐报告。

人工校勘放在 `data/liuxiaobiao-corrections.json`，不会被导入覆盖。格式如下，键仍为“章节名:条目序号”；`notes: []` 表示人工确认不附注文：

```json
{
  "德行:1": {
    "notes": ["人工复核后的原注"],
    "reason": "底本页码及核对依据",
    "reviewer": "复核人"
  }
}
```

更新底本时应同时更新来源修订号与摘要，并复查人工记录。导入器先验证全部输出再替换生成文件。报告有待复核/失败条目时仍可构建，结构不合法则导入失败。

```bash
npm run import:liu-notes -- sources/kanripo.txt
npm run check           # 单元测试、全书结构/统计校验、构建
npx playwright install chromium
npm run test:e2e        # 桌面和移动视口，项目子路径访问
```

辅助注译加载失败时正文仍可阅读，并可单独重试。阅读位置按章节保存；刷新、字号、注译及横竖排切换恢复到原条目。存储不可用时仍可阅读，但无法跨刷新保存。位置只保存在当前浏览器，不跨设备同步。

阅读器中开启「注」后，词义小注仍显示朱砂「注」标识；有刘孝标原注的条目会额外显示可展开的「刘孝标注」。顶部「译」独立控制现代译文，默认关闭。
