# 中国古典文学 · Chinese Classics Reader

一个以中国古典诗文为中心的静态阅读站，现收录《唐诗选读》和《世说新语》，可直接构建并部署到 GitHub Pages。

## 书库与阅读

- **唐诗选读**：366 篇、86 位作者；诗题、作者、诗句检索，诗体筛选，保留分行，支持上一篇 / 下一篇；全366首附原创整理词注与逐行白话译文。
- **世说新语**：36 门、1128 则，保留词义注、刘孝标注与已有译文。
- 藏书首页统一入口，各书独立保存最近篇目与条目内阅读位置。
- 书目与阅读器分离：`data/catalog.json` 描述书目，`assets/library.mjs` 负责校验、内容适配和路由，`assets/reader.js` 负责共用交互。

## 功能

- 三十六门完整目录与逐则阅读
- 古籍米黄纸张 / 夜间护眼主题
- 横排 / 竖排一键切换
- 字号调节
- 左侧篇目导航与正文检索
- 阅读进度、章节定位、返回顶部
- 自动记忆主题、字号、排版方式、最近篇目与阅读位置
- 移动端抽屉目录
- 「原文 / 注释 / 译文」分层阅读；译文默认隐藏
- 刘孝标原注可折叠阅读
- 正文阅读无第三方运行时依赖；地图按需加载本地 Leaflet，适合 GitHub Pages

## 唐诗来源与再生成

唐诗正文来自 [chinese-poetry/chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)，固定版本为 `b8594f81a89752241442f2ce267d6f66f96704ee`。源文件虽名为“唐诗三百首”，实际标签集包含 366 篇，因此站内称“唐诗选读”，不宣称是标准三百首定本。

原始文件、来源摘要和 MIT 许可证位于 `sources/tang-poems/`，站点构建也保留数据许可证。OpenCC 仅在导入时转换简体，浏览器没有额外运行时依赖。正文保留该来源的异文，例如《静夜思》为“床前看月光”“举头望山月”，未擅自改写为通行教材版本；本批不附生成式注释或译文。

```bash
npm run import:tang-poems  # 从固定本地数据确定性生成，不联网
npm run check             # 同时校验书目、唐诗数据、许可及原有刘注
```

## 多书目路由与兼容

- `#/`：藏书首页，始终可选择两类作品。
- `#/book/tang-poems`：唐诗目录；同一目录支持诗题、作者、诗体及诗句筛选。
- `#/book/<book-id>/read/<work-id>`：稳定的篇目地址；诗题重名不会发生碰撞。
- 原有 `#/chapter/德行` 等链接会自动转入《世说新语》的新地址。

主题、字号、排版沿用原有偏好键；阅读进度改按书目保存为 `classics:<book-id>:positions`，首次打开《世说新语》时兼容旧 `ssxy_pos` 数据。首页提供继续阅读入口，不自动跳过书库。检索结果不覆盖正常阅读位置；跨书切换会忽略过期的正文或辅助加载结果。

新增书目时，添加正文 JSON 和 catalog 条目即可复用通用阅读器；`kind` 为 `prose` 或 `poetry`。诗歌条目必须有稳定 `id`、`title`、`author` 和分行 `content`；散文章节由原始顺序生成 `chapter-01` 等编号。所有内容需记录来源与许可，再运行数据校验。仓库名和 Pages 路径保留为 `shishuo-xinyu`，避免破坏既有部署地址。

## 世说新语正文来源与校勘说明

《世说新语》为公版古籍。本仓当前结构化正文初始化自公开古籍 JSON 语料，并以中国哲学书电子化计划（CTP）《世说新语》相关版本作为后续校勘参考。

- CTP: https://ctext.org/shi-shuo-xin-yu/zhs
- 数据初始化参考: https://github.com/hanzhaodeng/chinese-ancient-text
- 阅读器交互设计参考: https://github.com/hoveychen/guwen-reader

> 电子文本可能存在异体字、OCR 或整理误差。重要引文建议回查影印本；后续校勘记录应独立保存，不直接覆盖原始版本。

## 刘孝标注数据层

阅读器使用 `data/liuxiaobiao-notes.json` 保存与正文逐则对齐的刘孝标原注。底本来自 Kanripo / `kr-shadow/KR3` 的《世說新語-劉宋-劉義慶》，许可证为 **CC0-1.0**。

导入器已经从只处理「德行第一」升级为面向 **全书三十六门** 的分门对齐流程：

```bash
npm run import:liu-notes
```

导入时会：

1. 读取仓库内固定版本、记录 SHA-256 的 CC0 Kanripo 底本（支持传入本地路径）；
2. 分离正文与括号内刘孝标注文；
3. 将当前简体正文逐则与古籍底本顺序对齐；
4. 修复底本双栏转写 `/` 造成的阅读顺序；
5. 生成 `data/liuxiaobiao-notes.json`；
6. 生成 `data/liuxiaobiao-alignment-report.json`，记录每门匹配数量、低置信条目和失败条目。

简繁转换仅用于匹配，不修改正文或注文原字形。起点探针相似度达到 0.9，且整则正文相似度达到 0.95，才自动纳入展示；能定位但未达到标准的条目进入复核，找不到可靠起点的条目标记失败。结尾必须从该则正文独立定位，不使用下一个成功条目的起点作为边界。阈值是自动筛选措施，不代表已完成学术校勘。

底本存在卷次跳转，且“赏誉”分为上下两段，因此导入器按门类编号组合底本，不假定全书连续顺序。固定底本和来源摘要保存在 `sources/`；默认导入不联网。

当前 1128 则中：594 则通过自动检查（552 则有刘注、42 则未提取到注），426 则待复核，108 则对齐失败。未通过的条目不展示刘注；完整位置、分数与候选注文见对齐报告。

人工校勘放在 `data/liuxiaobiao-corrections.json`，不会被导入覆盖。格式如下，键仍为“章节名:条目序号”；`notes: []` 表示人工确认不附注文：

```json
{
  "德行:1": {
    "notes": ["人工复核后的原注"],
    "reason": "底本页码及核对依据",
    "reviewer": "复核人"
  }
}
```

更新底本时应同时更新来源修订号与摘要，并复查人工记录。导入器先验证全部输出再替换生成文件。报告有待复核/失败条目时仍可构建，结构不合法则导入失败。

```bash
npm run import:liu-notes -- sources/kanripo.txt
npm run check           # 单元测试、全书结构/统计校验、构建
npx playwright install chromium
npm run test:e2e        # 桌面和移动视口，项目子路径访问
```

辅助注译加载失败时正文仍可阅读，并可单独重试。阅读位置按章节保存；刷新、字号、注译及横竖排切换恢复到原条目。存储不可用时仍可阅读，但无法跨刷新保存。位置只保存在当前浏览器，不跨设备同步。

阅读器中开启「注」后，词义小注仍显示朱砂「注」标识；有刘孝标原注的条目会额外显示可展开的「刘孝标注」。顶部「译」独立控制现代译文，默认关闭。

## 名物研读与文学地名地图

工具栏“名物”首次默认关闭。开启后，正文地名和器物出现细线，点词先查看释义、原句语境和来源；地名提供 Google 地图今地检索，器物提供 Google 图片检索。外部网站仅在用户点击后访问，不嵌入搜索结果。桌面为右侧研读栏，手机为可关闭并支持键盘焦点恢复的底部弹层。

首批词库为 20 个地名和 20 个器物，当前底本共有 305 处字面候选：240 处通过本次语境校读，50 处排除，15 处待考。本次校读是阅读辅助，并非完成学术定本校勘。特别排除了“殷荆州”等人物代称、“琴赋”“广陵散”等作品名、“萧瑟”等形容词，以及“香炉瀑布”中的山峰用法；张祜《题金陵渡》在镇江的词例保留待考，不绑定南京。

`#/atlas` 是文学地名地图。可按书目、语境时期、古今名称检索，并切换全部地名或最近打开篇目的地名；选中地点查看相关诗文，点击原句回到正文并突出目标词。地图参数和词例定位可以直接分享，例如 `#/atlas?book=tang-poems&period=唐`，正文链接增加 `?mention=<词例ID>`。

地图为**现代山川底图与历史地名参考位置**，不显示未经核实的古代疆界，不推断人物活动路线。现代区域参考点为空心标记；荆州、汝南及汉唐关址有歧义的玉门关等仍可查词例，但首版不强行给坐标。同一地点参考位置合并显示计数。读者应查看每条位置说明，不能把图上参考点当作古城址或实测遗址。

### 数据维护与许可

- `sources/knowledge/entities.json`：自撰词条说明、检索词、资料出处、区域参考位置。
- `sources/knowledge/reviews.json`：逐处语境校读记录，绑定稳定篇目 ID、条目、UTF-16 范围和原句 SHA-256。
- `data/knowledge-entities.json`、`data/knowledge-mentions.json`：生成的阅读数据。只发布 reviewed 且原文一致的词例；原文变化后重新生成的未匹配词例为 candidate，旧复核记录列入报告。
- 历史地名优先参考 [CHGIS](https://chgis.fas.harvard.edu/)，但其 V6 发布许可限制再分发，因此本站只保留核查外链，不打包其 GIS 数据或坐标。
- 底图、海岸水系和现代城市参考点来自 Natural Earth **v5.1.2** 公有领域数据；来源和派生文件摘要见 `sources/maps/provenance.json`。城市参考点独立来自该开放数据，不是 CHGIS 坐标。
- Leaflet 固定为 **1.9.4 / BSD-2-Clause**，本地文件和许可证位于 `assets/vendor/leaflet/`；只有进入地图时才加载，不依赖 CDN、在线瓦片、Google API key 或账户。

```bash
npm run build:knowledge  # 本地生成候选与词例，未匹配复核不自动通过
npm run vendor:leaflet   # 从固定 npm 开发依赖复制本地地图运行库和许可证
npm run check           # 检查词例范围、出处、正文摘要、坐标与地图资源摘要
npm run test:e2e        # 包含地图筛选、词例回跳、弹层焦点及失败恢复
```

地图不加载时不影响正文；Google 无法访问时，仍能使用站内资料、地名索引及复制检索词。馆藏链接用于核查和对照，Google 图片结果不代表本文所指器物的确定形制或年代。

## 唐诗注解与译文

全部366首已配1,751行白话译文与1,065处定位词注。点工具栏“注”查看重点字词，点“译”显示紧随原行的译文；两者首次默认关闭，沿用原阅读偏好。与名物重叠的词合并一个入口。每首末尾可展开“注译说明与参考资料”，查看整理方式、异文和题署疑点。

内容为模型辅助原创整理与逐行自校，**没有经过独立专家审校**。它是阅读辅助，学术引用仍需对照可靠校本。正文底本不改写，错署作者、重复诗和异文均保留，并在相关篇目说明；“乃与秦塞通人烟”与“不与秦塞通人烟”等语义不同的异本分别翻译。未复制现成现代译文。

- `data/tang-poems-study.json`：浏览器使用的独立资源，以稳定篇目ID绑定每行原文、SHA-256、译文、词注UTF-16范围、参考资料和自校状态。
- `sources/tang-poems/study/001.tsv` 至 `006.tsv`：按底本顺序分批撰写的原稿。每行依次为篇目索引、以 `|` 分隔的逐行译文、以 `;` 分隔的 `原词=解释`、可选篇目说明，列间为真实制表符。无需词注的诗行记录原因；标题词义归入篇目说明。
- `works.json` 把原稿索引固定到篇目ID和底本指纹，防止重新排序导致串注；`reuse.json` 仅列人工确认的同诗异文复用与差异行覆盖。完全同文可复用原创译文，但仍各自绑定ID、原文及题署。
- `reviews.json` 是逐首自校记录，含原稿摘要、底本摘要、状态和核对项目；状态只在正文逐行对应、句义与否定、典故语境、词注位置核对后记录为 `reviewed`。草稿和待复核不可发布。词义与史实补充参考见 `references.json`，仅保存来源链接，不抓取或嵌入第三方现代注译。

```bash
npm run build:tang-study   # 校验原稿/底本与自校记录，再生成资源
npm run check:data         # 包括366首、1751行、定位与指纹的完整校验
npm run check
npm run test:e2e
```

维护时先修改原稿，完成自校后明确更新对应自校记录。原稿或正文变化会使摘要失效，生成器会拒绝发布，不能靠重新生成自动“通过复核”。浏览器也核验正文和范围、加载时核验SHA-256；资源无效会隐藏注译并提供重试，正文可继续阅读。原稿摘要按生成器中确定的 `{translations, notes, remarks}` 结构JSON计算；底本摘要按对应完整篇目JSON计算。
